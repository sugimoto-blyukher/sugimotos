# 画像描画のために必要な過程

このリポジトリには現時点でフレームバッファやGPU向けの実装がなく、画像描画は未実装です。
以下は、このOSで画像描画機能を追加するために必要な過程の整理です。

## 1. 目的と前提の整理
- 描画先: フレームバッファ (MMIO) / 仮想GPU / 既存SBI拡張
- 画面仕様: 解像度、ピクセルフォーマット (RGB565 / XRGB8888 など)
- 描画モデル: 直接描画 / バックバッファ / 2Dアクセラレータ

## 2. デバイス検出と初期化
- デバイスツリー (FDT) から描画デバイス情報を取得
- 物理アドレスとサイズを把握
- ページングがある場合はMMIO領域をマップ
- 必要なら初期化レジスタを書き込み

## 3. フレームバッファの扱い
- フレームバッファ先頭アドレスを保持
- ピクセルフォーマットに合わせた書き込み関数を用意
- 行ピッチ (stride) を考慮してアドレス計算

## 4. 画像データの用意
- 画像形式を決める: 生データ (RAW) か圧縮形式 (BMP/PNG/JPEG)
- 圧縮形式の場合はデコーダを実装/組み込み
- 画像をメモリにロード (ビルトイン配列 / ファイルシステム / ネットワーク)

## 5. 描画処理
- 画像のピクセルをフレームバッファへコピー
- 必要なら色変換 (例: RGB888 -> RGB565)
- 画面範囲外のクリッピング
- 透明色やアルファの扱い (必要に応じて)

## 6. 表示反映
- 直接フレームバッファなら即時反映
- バックバッファなら swap / blit を実装
- キャッシュ操作が必要なら flush/invalidate を実施

## 7. 最小API例
- `void fb_init(void)`
- `void fb_putpixel(int x, int y, uint32_t rgba)`
- `void fb_blit(int x, int y, const uint8_t *img, int w, int h)`

## 8. 動作確認
- 単色塗りつぶし (全画面)
- グラデーション描画
- 固定画像の描画
- 座標系とクリッピングの検証
