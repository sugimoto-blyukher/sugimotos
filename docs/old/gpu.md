# GPUおよび描画システムの制御

このOSは、QEMU等の仮想化環境で一般的に使用される **Virtio-GPU** デバイスを利用して描画を行います。システムの設計方針として、カーネルはデバイスの物理的な制御とバッファの転送のみを担当し、高度な描画ロジック（ウィンドウの合成、フォントのレンダリング等）はユーザーランド（Window Manager）で行う「マイクロカーネルに近いアプローチ」を採用しています。

## 1. 全体アーキテクチャ

描画システムは以下の4つのレイヤーで構成されています。

1.  **Hardware Layer (Virtio-GPU):** 2Dアクセラレーション機能を持つ仮想GPU。
2.  **Kernel Layer (Driver):** `kernel/drivers/virtio_gpu.c` が担当。Virtioプロトコルを用いた低レイヤー制御。
3.  **System Call Interface:** ユーザーランドとカーネルを繋ぐインターフェース。
4.  **User-land Layer (WM):** `user/user_wm_runtime.c` が担当。実際のウィンドウサーバーとして機能。

---

## 2. カーネルランドでの制御

### Virtio-GPU ドライバ (`kernel/drivers/virtio_gpu.c`)
カーネル内のドライバは、GPUハードウェアとの通信を管理します。

-   **初期化:** MMIO経由でデバイスを認識し、Virtqueueをセットアップします。
-   **リソース管理:** GPU側に「2Dリソース（フレームバッファ）」を作成し、カーネルが確保した物理メモリ（バックバッファ）をバックエンドとして紐付けます。
-   **画面更新 (`virtio_gpu_present`):**
    1.  `VIRTIO_GPU_CMD_TRANSFER_TO_HOST_2D`: 物理メモリからGPU内部のホストバッファへデータを転送します。
    2.  `VIRTIO_GPU_CMD_RESOURCE_FLUSH`: ホストバッファの内容を実際のディスプレイ画面に反映します。
-   **割り込み処理:** GPUからのコマンド完了通知を受け取り、待機中のプロセスを起床させます。

### ウィンドウマネージャ（カーネル版）
`kernel/gui/wm.c` にもWMの実装がありますが、現在のシステムでは主にユーザーランド版のWMがメインで動作し、カーネル版はブート時やエラー時のフォールバックとして機能します。

---

## 3. ユーザーランドでの制御 (Window Manager)

このOSの最大の特徴は、**ウィンドウマネージャがユーザーランドで「ソフトウェアレンダリング」を行っている**点です。

### Window Manager (`user/user_wm_runtime.c`)
ユーザープロセスの `user_init` などがWMライブラリを含んで動作します。

-   **ソフトウェア・バックバッファ:** `u_mmap` を使用して、ユーザーランドに画面全体のピクセルデータを保持するメモリ領域を確保します。
-   **ウィンドウ合成 (Composition):**
    -   背面のウィンドウから順番に、確保したバックバッファへピクセルを書き込みます（ペインターアルゴリズム）。
    -   `wm_gpu_draw_window_rect`: ウィンドウの枠、タイトルバー、閉じるボタンを描画します。
    -   `wm_gpu_draw_glyph_5x7`: ビットマップフォントを使用してテキストをレンダリングします。
-   **入力制御:** マウスの移動やクリックイベントを処理し、ドラッグによるウィンドウ移動やリサイズを計算します。
-   **Dirty Rect管理:** 変更があった領域のみを再描画する最適化を行い、CPU負荷を軽減しています。

---

## 4. 描画のシーケンス

アプリケーションが画面を更新する際の流れは以下の通りです。

1.  **アプリの要求:** ユーザーアプリが `u_wm_set_text` や `u_wm_set_image` を呼び出し、WMに描画内容を伝えます。
2.  **合成:** WMが内部のソフトウェアバッファにウィンドウやボタン、カーソルを書き込み、1枚のフレームを完成させます。
3.  **システムコール発行:** WMが `SYS_GPU_PRESENT(buffer, size)` を発行します。
4.  **カーネルの処理:** 
    -   カーネルはユーザーバッファからカーネル内のGPUバックバッファへ `memcpy` でデータをコピーします。
    -   その後、GPUデバイスへ転送コマンドを送出します。
5.  **ハードウェア反映:** GPUがホストの画面を更新します。

## 5. 主要なシステムコール

| システムコール | 説明 |
| :--- | :--- |
| `SYS_GPU_INIT` | GPUドライバを初期化します。 |
| `SYS_GPU_INFO` | 画面の解像度 (Width, Height, Pitch) を取得します。 |
| `SYS_GPU_PRESENT` | 指定したユーザーバッファを画面に反映します（実質的なFlip）。 |
| `SYS_MMAP` | 描画用や画像用のメモリ領域を確保するために使用されます。 |

## 6. 技術的な制限と将来の展望
-   **ソフトウェアレンダリング:** 現在は全ての描画をCPUで行っているため、高解像度ではCPU負荷が高くなります。将来的にVirtio-GPUの3D機能やハードウェアアクセラレーションを利用することで改善が可能です。
-   **ダブルバッファリング:** WM側とカーネル側で二重にバッファを持っており、コピーが発生しています。共有メモリ（Zero-copy）を利用した最適化の余地があります。
