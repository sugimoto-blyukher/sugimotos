# Virtio-GPU ドライバの仕組み

このドキュメントでは、`kernel/drivers/virtio_gpu.c` における Virtio-GPU ドライバの内部実装と、ハードウェア（QEMU 等）との通信の仕組みについて解説します。

## 1. デバイスの認識と初期化

このドライバは **Virtio-MMIO** (Memory Mapped I/O) 規格に基づいています。

-   **Discovery:** `VIRTIO_MMIO_BASE` (0x10001000) から各スロットを走査し、マジック値 (`0x74726976`)、デバイスID (`16` = GPU) を確認してデバイスを特定します。
-   **Status 設定:** 規格に従い、`ACKNOWLEDGE` -> `DRIVER` -> `FEATURES_OK` -> `DRIVER_OK` の順にステータスを書き込み、初期化を完了させます。
-   **解像度の取得:** `VIRTIO_GPU_CMD_GET_DISPLAY_INFO` コマンドを送出し、ホスト（エミュレータ）側で設定されている解像度を取得します。

## 2. Virtqueue (通信路) の構造

GPU とのコマンドやり取りには、**Virtqueue** という共有メモリ構造を使用します。このドライバでは 1 つのキュー（制御用）を使用します。

-   **Descriptor Table:** 32 個のエントリ。各エントリは「メモリのアドレス」と「長さ」を指します。通常、[0] がリクエスト（送信データ）、[1] がレスポンス（受信データ）としてペアで使われます。
-   **Available Ring:** ドライバが GPU に処理を依頼した記述子のインデックスを格納します。
-   **Used Ring:** GPU が処理を終えた記述子のインデックスを格納します。

## 3. コマンド送出シーケンス (`vg_submit`)

コマンドの送出は以下の手順で行われます：

1.  記述子 [0] にリクエスト構造体をセットし、`NEXT` フラグを立てて [1] に繋げます。
2.  記述子 [1] にレスポンス構造体をセットし、`WRITE` フラグを立てます。
3.  `Available Ring` に記述子 0 を書き込み、インデックスをインクリメントします。
4.  MMIO レジスタ `VG_MMIO_QUEUE_NOTIFY` に `0` を書き込み、GPU に通知します。
5.  `Used Ring` にデータが戻ってくるまで、`wfi` (Wait For Interrupt) または `waitq_sleep` で待機します。

## 4. 描画リソースのセットアップ

画面を表示するために、以下の 3 つのリソース設定を順番に行います。

1.  **Resource Create 2D:** 内部的なリソースID (通常 1) を割り当て、幅・高さ・フォーマットを定義します。
2.  **Resource Attach Backing:** カーネルが `alloc_pages` で確保した**物理メモリ（バックバッファ）**を、GPU のリソースに紐付けます。これにより、メモリへの書き込みが GPU 側に伝わる準備が整います。
3.  **Set Scanout:** 作成したリソースを、実際の画面出力（スキャンアウト）として指定します。

## 5. 画面更新プロセス (`virtio_gpu_present`)

カーネルまたは WM がバックバッファにピクセルデータを書き込んだ後、画面に反映させるには 2 段階のコマンドが必要です。

1.  **Transfer to Host 2D:**
    ゲスト（OS側）のメモリにあるピクセルデータを、ホスト（GPU側）の内部バッファへコピーするよう指示します。
2.  **Resource Flush:**
    ホスト側の内部バッファから、実際の画面（ウィンドウやディスプレイ）へ内容を「掃き出す」よう指示します。

## 6. 割り込み処理 (`virtio_gpu_handle_irq`)

GPU がコマンドの処理を終えると、割り込みが発生します。

-   `VG_MMIO_INTERRUPT_STATUS` を読み取り、割り込み原因を確認します。
-   `VG_MMIO_INTERRUPT_ACK` で割り込みをクリアします。
-   `waitq_wake_all` を呼び出し、`vg_submit` で待機していたプロセスを再開させます。
-   同時に `kevent_push` を行い、カーネルのイベントキューに GPU イベントを通知します。

## 7. メモリ管理とアライメント

Virtio はハードウェアとメモリを共有するため、データ構造のアライメントが厳格です。

-   `vg_desc`, `vg_avail`, `vg_used` はそれぞれ 16, 2, 4 バイトのアライメントが指定されています。
-   バックバッファはページ境界 (`PAGE_SIZE`) で確保され、GPU にはその物理アドレスが渡されます。
-   ピクセルフォーマットは `B8G8R8A8_UNORM` (32bit) が固定で使用されます。
